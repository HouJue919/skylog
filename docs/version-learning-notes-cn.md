# SkyLog 版本学习笔记

这份文档记录 SkyLog 从 v0.1 到 v1.0 每个阶段做了什么、学到了什么、为什么重要。

## v0.1 静态 App 原型

### 做了什么

- 创建 Flutter 项目
- 把默认计数器 App 改成 SkyLog 首页
- 加入底部导航
- 创建 Home、Logs、Add、Map、Profile 五个主页面
- 使用静态数据展示 App 的基本结构

### 学到什么

- Dart 是编程语言，Flutter 是用 Dart 做 App 的框架
- `main()` 是 App 的入口
- Flutter 里的界面由 Widget 组成
- `StatelessWidget` 适合不需要变化的界面
- `StatefulWidget` 适合需要记住变化的界面
- `NavigationBar` 可以做底部导航
- `IndexedStack` 可以根据当前 tab 显示不同页面

### 为什么重要

v0.1 让 SkyLog 从想法变成了可以运行的 App 原型。虽然还不能保存真实数据，但已经能展示产品结构和主要页面。

## v0.2 可交互新增记录

### 做了什么

- 创建 `FlightRecord` 数据模型
- 用 `List<FlightRecord>` 保存多条飞行记录
- Add 页面可以创建一条新飞行记录
- 保存后自动跳到 Logs 页面
- Logs 页面显示新增的记录

### 学到什么

- 数据模型可以把相关信息组织在一起
- `List` 可以保存多条同类数据
- `TextEditingController` 可以读取输入框内容
- `setState()` 可以让界面根据数据变化重新显示
- 子页面可以通过 callback 把数据传回父页面

### 为什么重要

v0.2 让 SkyLog 从静态原型变成可交互原型。用户第一次可以输入数据，并看到 App 根据输入发生变化。

## v0.3 本地保存 MVP

### 做了什么

- 加入 `shared_preferences`
- 把飞行记录转成 JSON 保存到本地
- App 启动时读取本地记录
- 新增记录后重新打开 App，记录仍然存在
- 支持删除记录
- 添加 Logs 空状态

### 学到什么

- 本地存储可以让数据在 App 重启后保留
- JSON 是一种常见的数据交换和保存格式
- `toJson()` 可以把对象转成可保存的数据
- `fromJson()` 可以把保存的数据还原成对象
- `async` / `await` 用来处理需要等待的操作
- 删除数据后也要同步更新本地存储

### 为什么重要

v0.3 是 SkyLog 进入 MVP 的关键一步。数据不再只存在内存里，而是可以真正保存和恢复。

## v0.4 详情页和表单校验

### 做了什么

- Logs 里的记录可以点击进入详情页
- 详情页显示飞行数据、地图位置和总结
- Add 页面加入正式 `Form` 校验
- 标题、地点、时长为空时显示错误提示

### 学到什么

- `Navigator` 可以进行页面跳转
- `MaterialPageRoute` 可以打开新页面
- `Form` 和 `validator` 可以做输入校验
- 详情页可以让一条数据被完整查看
- 好的表单需要在用户出错时给清楚提示

### 为什么重要

v0.4 让 SkyLog 不只是列表，而是有完整记录详情。表单校验也让 App 更稳定、更像真实产品。

## v0.5 早期试用准备

### 学到什么

- App 不只需要功能，也需要让用户知道当前版本和状态
- 早期测试需要明确告诉用户应该测试什么
- 表单保存后重置可以减少连续输入时的混乱
- 项目文档也是产品开发的一部分

### 为什么重要

v0.5 让 SkyLog 更适合给熟人做小范围演示。它开始从“自己能用”走向“别人能理解”。

## v0.7 飞行日志搜索

### 做了什么

- Logs 页面加入真实搜索框
- 可以按标题、地点、日期、时长、无人机、天气和总结搜索
- 搜索无结果时显示提示
- 添加清除搜索按钮

### 学到什么

- `TextField` 可以接收用户输入
- `onChanged` 可以在输入变化时立刻响应
- `List.where()` 可以过滤列表
- `contains()` 可以判断字符串是否包含关键词
- 搜索功能本质上是“输入 -> 过滤数据 -> 更新界面”

### 为什么重要

SkyLog 的核心价值之一是让历史飞行可以被找回来。搜索让 Logs 页面从展示列表变成真正可用的记录工具。

## v0.8 编辑已有记录

### 做了什么

- 详情页加入 Edit / Save
- 可以修改已有飞行记录
- 保存后 Logs 页面同步更新
- 编辑后的数据继续保存在本地

### 学到什么

- CRUD 包括 Create、Read、Update、Delete
- `indexOf()` 可以找到要修改的数据
- 详情页可以有查看模式和编辑模式
- `late` 可以用于稍后初始化 controller
- 子页面可以提交修改，让父组件更新主数据列表

### 为什么重要

v0.8 完成了基础 CRUD。用户不仅能新增和删除，也能修正错误信息，这让 App 更接近真实可用。

## v0.9 Dashboard 和截图准备

### 做了什么

- Dashboard 统计改成根据真实记录计算
- 最近飞行和最近日志使用真实数据
- 新增中文截图计划

### 学到什么

- 首页统计应该来自真实数据，而不是固定假数字
- 可以从 List 中计算总数和总时长
- 展示型项目需要提前规划截图
- 作品集材料也是长期项目的一部分

### 为什么重要

v0.9 让 SkyLog 的展示更真实，也开始为作品集和项目展示做准备。

## v1.0 MVP 完成

### 做了什么

- 制定 v1.0 checklist
- 编写中文项目总结
- 添加完整 v1 workflow 测试
- 验证主流程：

```text
Add -> Save -> Search -> View Detail -> Edit -> Delete -> Export
```

### 学到什么

- 一个 MVP 需要有明确完成标准
- 自动测试可以验证核心流程
- 项目不是功能越多越好，而是核心流程稳定最重要
- 阶段性总结可以帮助自己真正理解项目

### 为什么重要

v1.0 是 SkyLog 的第一个完整里程碑。它证明这个项目已经从想法、原型、交互、本地保存，发展成了一个有核心闭环的本地优先飞行日志 MVP。

- 更新版本状态为 `SkyLog v1.1`

- 作品集需要清楚展示当前版本、功能和使用场景
- 自动测试可以帮助确认打磨 UI 时没有破坏核心功能

### 为什么重要

v1.1 让 SkyLog 更适合被展示。它开始从“开发项目”过渡到“可以讲给别人听的作品集项目”。

## v1.2 飞行前检查清单

### 做了什么

- 把占位 Map tab 换成 Pre-flight Checklist
- 加入 6 个飞行前安全检查项
- 勾选状态会保存在本地
- Home 页面显示检查进度
- 加入 Reset Checklist
- 添加自动测试，验证勾选和重置流程

### 学到什么

- `Set<int>` 适合保存“不重复的一组选中项目”
- checkbox 适合做二选一状态
- 本地存储不只可以保存飞行记录，也可以保存用户界面状态
- 产品功能应该围绕真实使用场景，而不是只加看起来酷的页面

### 为什么重要

v1.2 让 SkyLog 不只是在飞行后记录，也开始帮助飞行前准备。这个版本让项目更像真实无人机用户会需要的工具。

## v1.3 检查清单连接飞行记录

### 做了什么

- 给 `FlightRecord` 增加 checklist 完成度字段
- Add Flight 会把当前 checklist 完成情况保存进新记录
- 保存飞行后自动清空 checklist，准备下一次飞行
- Logs 卡片显示 `6/6 checks` 这种检查状态
- Detail 页面显示这次飞行前是否完成检查
- JSON 导出也包含 checklist 数据

### 学到什么

- 数据模型会随着产品功能成长
- 给旧数据加新字段时，要设置默认值，避免旧记录读取失败
- 一个功能如果能连接到核心数据，就比孤立页面更有价值
- 自动测试可以覆盖跨页面流程：Checklist -> Add -> Logs -> Detail

### 为什么重要

v1.3 把“飞行前准备”和“飞行后记录”连起来了。这个版本让 SkyLog 的使用流程更完整，也更容易向别人解释产品价值。

## v1.4 公开 Beta 稳定化

### 做了什么

- 更新版本状态为 `SkyLog v1.4`
- Profile 增加 About This Beta 说明
- Profile 增加 Privacy and Local Data 说明
- 解释 SkyLog 是记录工具，不是飞控 App 或官方安全系统
- 解释数据目前保存在本机，不会上传到云端
- 添加自动测试，确认两个说明弹窗可以打开

### 学到什么

- 准备公开测试不只是修 bug，也要减少用户误解
- 隐私和数据说明是产品可信度的一部分
- beta 版本要清楚说明“能做什么”和“不能做什么”
- 稳定化阶段可以先补齐说明、测试和边界，再继续加大功能

### 为什么重要

v1.4 让 SkyLog 更接近可以给别人试用的状态。别人打开 App 时，不只看到功能，也能理解这是一个本地优先的 beta 工具。

## v1.5 测试反馈工具包

### 做了什么

- 更新版本状态为 `SkyLog v1.5`
- Profile 增加 Copy Feedback Template
- 反馈模板会给 tester 一组具体问题
- 尝试把模板复制到剪贴板
- 即使剪贴板慢或失败，也会显示模板弹窗
- 更新 early tester guide
- 添加自动测试，确认反馈模板可以打开

### 学到什么

- beta 测试需要结构化反馈，而不是只问“感觉怎么样”
- App 可以帮助引导 tester 做更有价值的测试
- 剪贴板这类系统能力可能失败，所以 UI 要有 fallback
- 稳定化阶段关注的是“别人能不能顺利试用和反馈”

### 为什么重要

v1.5 让 SkyLog 更适合小范围外部试用。别人试完以后可以直接按模板反馈，你也更容易把反馈整理成下一轮迭代方向。

## v1.6 Beta 发布检查清单

### 学到什么

- 固定网页上线前，要先确认 tester 不会误解数据、隐私和安全边界

### 为什么重要

v1.6 让 SkyLog 更接近固定网页部署前的状态。它没有急着加功能，而是建立了发布前的质量门槛。

- 明确说明数据只保存在当前浏览器/设备
- 提醒 tester 使用样例或非敏感数据

- 更新 early tester guide 和 beta release checklist

- 稳定化阶段的重点是降低误解和支持成本

### 为什么重要

v1.7 让 SkyLog 更接近固定网页 beta。别人打开网页前后，都能清楚知道数据、隐私、安全边界和测试流程。

## v1.8 部署准备

### 做了什么

- 更新版本状态为 `SkyLog v1.8`
- Profile 增加 Deployment Readiness
- 新增 `docs/deployment-readiness.md`
- 记录固定网页前需要运行的命令：

```text
flutter analyze
flutter test
flutter build web
```

- 验证 Flutter Web 构建成功，生成 `app/build/web/`

### 学到什么

- 部署前不能只看 App 能不能在 VS Code 跑
- Web build 是固定网页上线前的重要检查
- `build/web` 是之后部署到 GitHub Pages 或 Netlify 的静态文件
- 上固定网页之前还要确认隐私说明、测试说明和反馈流程都清楚

### 为什么重要

v1.8 证明 SkyLog 已经具备生成网页版本的能力。它还没有正式部署，但已经完成部署前的技术检查。

## v1.9 固定网页 Beta 路线

### 做了什么

- 更新版本状态为 `SkyLog v1.9`
- Profile 增加 Fixed Web Beta Path
- 新增 `docs/fixed-web-beta-path.md`
- 新增 `.github/workflows/deploy-web.yml`
- 规划第一条固定测试链接使用 GitHub Pages
- 说明固定链接仍然只给 3-5 个可信 tester
- 添加自动测试，确认固定网页路线弹窗可以打开

### 学到什么

- 部署不是只把文件放到网上，还要有稳定、可重复的流程
- GitHub Actions 可以把 analyze、test、build、deploy 串起来
- Flutter Web 部署到子路径时，需要设置 `base-href`
- “固定网址”不等于“公开发布”，beta 分享范围仍然要控制

### 为什么重要

v1.9 把 SkyLog 从“可以构建网页”推进到“有固定网页 beta 路线”。这一步让之后真正部署到 GitHub Pages 更清楚，也更适合作为长期项目记录。

### 为什么重要

v2.0 让 SkyLog 从“可以被别人打开”进入“可以被别人有结构地测试”。这对长期项目和大学申请都重要，因为它证明项目有真实用户反馈和迭代过程。

## v2.1 自动网页部署

### 做了什么

### 为什么重要

v2.1 让 SkyLog 的发布流程更像真实项目：本地开发、自动测试、提交、推送、自动部署。以后每个稳定版本都可以更快同步到固定网页。

## v2.4 网页更新提示

### 做了什么

- 更新版本状态为 `SkyLog v2.4`
- Profile 增加 Web Update Tips
- 新增 `docs/web-update-guidance.md`
- 说明如果网页还显示旧版本，可以刷新、开无痕窗口、换浏览器或清除站点数据
- 更新 early tester guide 和 beta release checklist
- 添加自动测试，确认网页更新提示弹窗可以打开

### 学到什么

- Web App 部署成功不代表每个浏览器马上看到新版
- 浏览器缓存和 service worker 可能让 tester 看到旧版本
- beta 测试不仅要写功能，也要处理真实使用时的困惑
- 好的项目会把遇到的问题转成说明和流程

### 为什么重要

v2.4 来自真实问题：我们已经遇到过线上文件更新了，但浏览器还显示旧版。这个版本把问题变成 tester 可以理解和解决的说明。

## v2.5 创作复盘字段

### 做了什么

- 更新版本状态为 `SkyLog v2.5`
- 给飞行记录增加 `Purpose`、`Issues`、`Next Improvements`
- Add Flight 页面可以填写飞行目的、问题和下次改进
- Flight Detail 页面可以查看和编辑这些复盘内容
- 搜索和 JSON 导出也包含这些新字段
- 添加自动测试，确认新字段能保存并在详情页显示

### 学到什么

- App 的数据模型可以随着产品目标慢慢变大
- 给旧数据设置默认值，可以避免以前保存的记录坏掉
- 功能不一定要很复杂，关键是更贴近用户真实流程
- AI 功能之前，先把高质量输入字段做好更重要

### 为什么重要

v2.5 是从“记录飞行”走向“记录成长”的一步。以后如果加入 AI 总结、作品集生成或训练建议，这些字段会成为更好的输入材料。

## v2.6 地图坐标准备

- 可选字段适合 beta 阶段，因为 tester 不一定知道准确 GPS
- 数据模型升级时，要让旧记录继续能正常打开
- UI 预览可以先表达功能方向，不必第一天就接复杂第三方服务

### 为什么重要

原初技术方案 Sprint 3 写了“经纬度保存”和“轻量地图”。v2.6 先把坐标数据打通，后面才有基础做地图点位、系统地图跳转或素材位置管理。

## v2.7 素材元数据

### 为什么重要

原初技术方案 Sprint 3 写了图片选择、封面图和素材画廊。v2.7 先做最轻量的素材关联，为以后接 `image_picker`、本地文件复制和素材画廊做准备。

### 为什么重要

原初技术方案 Sprint 4 写了首页统计、个人页统计和无人机设备管理。v2.9 先把 Profile 的真实统计打通，为以后 CSV 导出、设备管理和更完整的飞行报告做基础。

## v3.0 CSV 导出

### 做了什么

- 更新版本状态为 `SkyLog v3.0`
- Profile 增加 Export CSV Table
- CSV 导出包含标题、地点、坐标、日期、时长、无人机、天气、素材、复盘和 checklist
- CSV 文本会复制到剪贴板，也会在弹窗里预览
- 添加自动测试，确认 CSV 导出弹窗可以打开并包含记录内容

### 学到什么

- JSON 适合完整备份，CSV 适合表格查看和分析

- CSV 需要处理逗号、引号和换行，否则表格会错列
- 先做复制文本，比直接做文件下载更简单稳定

### 为什么重要

原初技术方案 Sprint 4 写了 JSON 导出和可选 CSV 导出。v3.0 让 SkyLog 的数据更容易放进 Numbers、Excel 或 Google Sheets 里复盘，也让项目更像一个完整的数据工具。

## v3.1 设备档案摘要

### 做了什么

- 更新版本状态为 `SkyLog v3.1`
- Profile 的 My Drones 不再只显示飞行次数
- 每台无人机会显示总飞行次数、总飞行时间、最近一次飞行日期
- 每台无人机会显示有坐标记录和有素材记录的数量
- 添加自动测试，确认设备摘要来自真实飞行记录

### 学到什么

- 同一个字段可以从“文本输入”升级成“统计对象”
- 设备管理可以先从自动汇总开始，不一定马上做复杂编辑页面
- 先做 read-only summary，风险比马上做新增、编辑、删除设备更低
- 真实产品经常先让用户看到价值，再决定是否加更复杂的管理功能

### 为什么重要

原初 PRD 写了 My Drones 和 DroneProfile。v3.1 先把飞行记录里的无人机型号自动整理成设备档案摘要，让 Profile 更像真正的飞行管理页面，同时保持 app 结构简单稳定。

## v3.2 备份报告

### 做了什么

- 更新版本状态为 `SkyLog v3.2`
- Profile 的 Data 区增加 Backup Report
- Backup Report 显示记录数量、总飞行时间、有坐标记录和有素材记录
- Backup Report 说明 JSON backup、CSV table 和 Local device
- 添加自动测试，确认备份报告展示正确数据

### 学到什么

- 备份功能不只是“有按钮”，还要让用户理解数据在哪里、导出包含什么
- 本地优先 app 必须清楚说明风险：换设备或清浏览器数据可能丢记录
- 在没有云同步之前，清晰的导出说明就是产品信任感的一部分
- 小版本可以专门改善“解释和信任”，不一定每次都加复杂功能

### 为什么重要

原初 Sprint 4 写了统计、设备和备份。v3.2 把备份部分从 JSON/CSV 按钮升级成更清楚的备份状态说明，让用户知道导出前后应该注意什么，也让 Sprint 4 更完整。

## v3.3 AI Prompt Preview

### 做了什么

- 更新版本状态为 `SkyLog v3.3`
- Flight Detail 增加 AI Readiness 区域
- 增加 Preview AI Prompt 按钮
- 弹窗显示未来 AI 总结功能可能使用的 prompt
- 明确说明不会联网、不会调用 API、不会使用 API key
- 添加自动测试，确认 AI Prompt Preview 可以打开

### 学到什么

- 真正接 AI 之前，应该先想清楚数据边界
- 前端 App 不能直接保存 API key
- AI 功能应该先做 prompt preview，再做本地 draft，再考虑真实 gateway
- AI 输出应该是可编辑草稿，不应该代替用户判断

### 为什么重要

Sprint 5 的主题是 AI 和数据增强，但 SkyLog 的基础记录功能不能依赖 AI。v3.3 先做 AI Readiness，让项目开始进入 AI 阶段，同时避免 API key 泄露、成本失控和隐私边界不清的问题。
